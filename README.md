# Online Struggle Detection and Anticipation

[![arXiv](https://img.shields.io/badge/arXiv-2512.09847-b31b1b.svg)](https://arxiv.org/abs/2512.09847)
[![Dataset: EvoStruggle](https://img.shields.io/badge/Dataset-EvoStruggle-blue.svg?logo=github)](https://github.com/FELIXFENG2019/EvoStruggle)

This is the code release corresponding to the paper titled ["From Detection to Anticipation: Online Understanding of Struggles across Various Tasks and Activities"](https://arxiv.org/abs/2512.09847).

The dataset used is [EvoStruggle](https://github.com/FELIXFENG2019/EvoStruggle/).

Struggle moment localization is reformulated as a causal, frame-level task: **online struggle detection** (is the person struggling at the current frame?) and **struggle anticipation** (will the person struggle in the next 2 seconds?), using only past and current observations. Two online action detection models are adapted as baselines:

| Directory | Model | Upstream |
|-----------|-------|----------|
| [`long-short-term-transformer/`](long-short-term-transformer) | LSTR | [amazon-science/long-short-term-transformer](https://github.com/amazon-science/long-short-term-transformer) |
| [`CMeRT/`](CMeRT) | CMeRT | [pangzhan27/CMeRT](https://github.com/pangzhan27/cmert.io) |

## 1. Installation

Both codebases share the same environment (see [`long-short-term-transformer/README.md`](long-short-term-transformer/README.md)):

```bash
conda create -n struggle python=3.7.7
conda activate struggle
pip install -r long-short-term-transformer/requirements.txt
# optional, to log training curves to Weights & Biases (SOLVER.ENABLE_WANDB True)
pip install wandb
```

## 2. Data Preparation

All configs expect the EvoStruggle dataset at `data/EvoStruggle/` in the root of this repository, and are run from inside the codebase directory (`cd CMeRT` or `cd long-short-term-transformer`), so that the relative paths `../data/EvoStruggle/...` resolve.

```bash
# from the root of this repository
mkdir -p data
git clone https://github.com/FELIXFENG2019/EvoStruggle.git data/EvoStruggle
# or, if you already have the dataset elsewhere:
# ln -s /path/to/EvoStruggle data/EvoStruggle
```

The models use **SlowFast features** (SlowFast-R50 pretrained on Kinetics, windows of 32 frames with a stride of 16 frames, i.e. one 2304-d feature every 0.32 s = 3.125 feature FPS). The first 2048 dimensions (Slow pathway) are used as visual input and the last 256 dimensions (Fast pathway) as motion input. The features are not distributed with the dataset; download the 360p videos (see the [download instructions](https://github.com/FELIXFENG2019/EvoStruggle#how-to-download)) into `data/EvoStruggle/data/360p/<Activity>/` and extract the features with the [EvoStruggle feature extractor](https://github.com/FELIXFENG2019/EvoStruggle/tree/main/extracted_features):

```bash
# from the root of this repository; requires PyTorch, torchvision and PyTorchVideo
for act in Tying_Knots Origami Tangram Shuffle_Cards; do
    python data/EvoStruggle/tools/video_feature_extractor.py --task $act
done
```

This writes `data/EvoStruggle/extracted_features/slowfast_features/<Activity>/<video>.npy`. The feature folder is set by `INPUT.FEATURE_DIR` in the configs (default `slowfast_features`).

The split for training on all four activities together, [`splits/combined_split.json`](splits/combined_split.json), is included. It merges the four within-activity splits and can be regenerated with `python tools/make_combined_split.py`.

## 3. Experiments

There is one config file per experiment of the paper, in `configs/Struggle/paper/` (CMeRT) and `configs/Struggle/LSTR/paper/` (LSTR). They are generated by [`tools/generate_struggle_configs.py`](tools/generate_struggle_configs.py) with the hyperparameters of Section 1 of the supplementary material.

| Experiment (paper) | Model | Configs | Train on | Test on |
|--------------------|-------|---------|----------|---------|
| Table 1, individual training | LSTR, CMeRT | `within_activity/lstr_<activity>_ant2s`, `within_activity/cmert_<activity>` | `train_attempt01`–`05` | `validation` |
| Table 1, combined training | LSTR, CMeRT | `combined/lstr_combined_ant2s`, `combined/cmert_combined` | `train` (all activities) | `validation` (all activities) |
| Fig. 2 (left), anticipation length 4/6/8 s | LSTR | `anticipation_length/lstr_<activity>_ant<N>s` | `train_attempt01`–`05` | `validation` |
| Table 2, activity-level generalization | CMeRT | `activity_generalization/cmert_activitygen_<activity>` | `train` (other three activities) | `test` (validation set of the held-out activity) |
| Table 3, task-level generalization | CMeRT | `task_generalization/cmert_taskgen_<activity>_task<XX>` | `train` (other tasks) | `test` (held-out task) |
| Figs. 6–8, skill evolution | CMeRT | `separate_attempts/cmert_sepattempt_<activity>_attempt<XX>` | `train_attempt<XX>` | `validation` |

`<activity>` is one of `tyingknots`, `origami`, `tangram`, `shufflecards`.

During training, the model is evaluated on the test subset after every epoch and a checkpoint is saved every epoch (CMeRT: from epoch 3). **The results in the paper are those of the best epoch on the test subset**, which is printed at the end of training (`Best ... on the test subset`).

### CMeRT

```bash
cd CMeRT

# train; checkpoints and logs are written to checkpoints/Struggle/paper/<experiment>/<config name>/
python main.py --config_file configs/Struggle/paper/within_activity/cmert_origami.yaml

# evaluate a checkpoint: prints the anticipation cAP for each future step (0.33 s ... 2 s), their mean
# (the "Ant." columns in the paper) and the online detection cAP ("Det.")
python main.py --test 1 --config_file configs/Struggle/paper/within_activity/cmert_origami.yaml \
    MODEL.CHECKPOINT checkpoints/Struggle/paper/within_activity/cmert_origami/epoch-<best>.pth MODEL.LSTR.INFERENCE_MODE batch
```

Any config value can be overridden on the command line. This is used for the experiments that evaluate a trained model on other data:

```bash
# Table 1 (combined training), evaluated on one activity
python main.py --test 1 --config_file configs/Struggle/paper/combined/cmert_combined.yaml \
    MODEL.CHECKPOINT <checkpoint> MODEL.LSTR.INFERENCE_MODE batch \
    DATA.DATA_SPLIT_PATH ../data/EvoStruggle/splits/separate_attempts/Origami/Origami_sepattempt.json \
    DATA.TRAIN_SEUBSET "['train_attempt01','train_attempt02','train_attempt03','train_attempt04','train_attempt05']"

# Fig. 4, zero-shot cross-activity evaluation: model trained on Origami, evaluated on Tangram
python main.py --test 1 --config_file configs/Struggle/paper/within_activity/cmert_origami.yaml \
    MODEL.CHECKPOINT <checkpoint> MODEL.LSTR.INFERENCE_MODE batch \
    DATA.DATA_SPLIT_PATH ../data/EvoStruggle/splits/separate_attempts/Tangram/Tangram_sepattempt.json

# Fig. 8, model trained on attempt 01, evaluated on the validation videos of attempt 05
python main.py --test 1 --config_file configs/Struggle/paper/separate_attempts/cmert_sepattempt_origami_attempt01.yaml \
    MODEL.CHECKPOINT <checkpoint> MODEL.LSTR.INFERENCE_MODE batch DATA.TEST_ATTEMPTS "['05']"
```

### LSTR

```bash
cd long-short-term-transformer

# train; checkpoints and logs are written to checkpoints/Struggle/LSTR/paper/<experiment>/<config name>/
python tools/train_net.py --config_file configs/Struggle/LSTR/paper/within_activity/lstr_origami_ant2s.yaml --gpu 0

# evaluate a checkpoint
python tools/test_net.py --config_file configs/Struggle/LSTR/paper/within_activity/lstr_origami_ant2s.yaml --gpu 0 \
    MODEL.CHECKPOINT checkpoints/Struggle/LSTR/paper/within_activity/lstr_origami_ant2s/epoch-<best>.pth MODEL.LSTR.INFERENCE_MODE batch
```

### Runtime / feature ablation (Table 5)

`CMeRT/configs/Struggle/cmert_s3dw32s16_long512_work8_kinetics_1x.yaml` (S3D features, `INPUT.FEATURE_DIR: s3d_features`) and `CMeRT/configs/Struggle/cmert_slowfastw32s32_long512_work8_kinetics_1x.yaml` (SlowFast with stride 32, `INPUT.FEATURE_DIR: slowfast_w32s32_features`) are trained on all four activities. These features have to be extracted separately and placed in the corresponding folder under `data/EvoStruggle/extracted_features/`.

## 5. Implementation Notes

- **Labels**: struggle segments are converted to frame-level labels by multiplying their start and end times by the feature frame rate (3.125 FPS); frames outside struggle segments are background.
- **Anticipation length** in feature frames is `ANTICIPATION_SECONDS × int(FPS)`, i.e. 2 s → 6 frames.
- **Evaluation subset**: `DATA.TEST_ATTEMPTS` (CMeRT, e.g. `"['05']"`) restricts the evaluation to the videos of some attempts.
